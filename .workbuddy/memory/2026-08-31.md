## 修复 4 个使用 bug（消息红点 / 无障碍 / 投屏闪退 / 摄像头音频）

### Bug1 消息未读红点 + 已读回执时序
- **根因**：`isViewing` 状态残留 true。仅靠 `MessageScreen.dispose()` 重置不可靠，残留后同时命中两个症状：
  - `isUnread = !isViewing && !msg.isFromMe` 恒 false → 首页红点不显示
  - `onIncoming` 里 `if (isViewing) _sendReadAll()` → PC 端消息提前变已读
- **修复**：
  - 新增全局 `routeObserver`（app.dart，注册到 `MaterialApp.navigatorObservers`）
  - `MessageScreen` / `HomeScreen` 实现 `RouteAware`（didPushNext / didPopNext）精确维护浏览态
  - `message_provider` 加 `forceExitViewing()` 兜底；`onConnected` 与 `markAllAsRead` 统一加 `unreadCount > 0` 保护，杜绝无条件回执
  - `setViewing` 改为幂等（状态未变直接 return）
- **架构事实**：消息与已读回执**完全走 WebRTC DataChannel P2P，server 零参与、零持久化**。回执类型是 `read_all`（无 messageId，全量），方向靠 `isFromMe` 区分，PC 端 `markAllAsRead('outgoing')`、App 端只处理 `isFromMe` 消息。

### Bug2 无障碍服务误报未开启
- **根因**：`RemoteControlService.onServiceConnected()` 用**全新 `AccessibilityServiceInfo()` 对象整体覆盖** `serviceInfo`，丢掉 XML 声明的 packageNames 与系统填充的 mId/resolveInfo → 系统判定配置无效并解绑服务 → `getEnabledAccessibilityServiceList()` 查不到 → 恒返回 false。叠加 XML 缺 `canRetrieveWindowContent="true"`。
- **修复**：改为基于 `serviceInfo` 增量修改并显式设 `canRetrieveWindowContent = true`；XML 补齐 `canRetrieveWindowContent` / `flagRetrieveInteractiveWindows`；`isServiceEnabled` 重排为「instance 存活 → Settings.Secure 按 ComponentName 精确匹配 → AccessibilityManager(FEEDBACK_ALL_MASK)」，且**不再中途提前 return**。

### Bug3 投屏闪退
- **根因**：`MediaProjectionService.onStartCommand` 的 **`throw e`**。Android 14+（targetSdk 35）在取得 MediaProjection 用户授权前启动 `FOREGROUND_SERVICE_TYPE_MEDIA_PROJECTION` 型 FGS 会抛 SecurityException，从主线程 onStartCommand 外泄 → ActivityThread 直接崩进程。
- **修复**：去掉 `throw e`，改为两级降级（mediaProjection type → 无 type）都失败也只记日志 + stopSelf；新增 `tryStartForeground()` 封装。Dart 侧 `screen_capture_service` 不再因 FGS 失败中断投屏。
- **顺带修掉的时序坑**：`MainActivity.startMediaProjectionService()` 原本调完 `startForegroundService()` 就无条件 `return true`，但它是异步的 → 改为轮询等待 `MediaProjectionService.isRunning`（上限 1s，25ms 步进），否则 `createVirtualDisplay()` 可能因 FGS 未就绪而失败。

### Bug4 摄像头音频同步
- **根因**：`camera_capture_service` 的 getUserMedia 写死 `'audio': false`，且**完全没有动态申请摄像头/麦克风权限**。
- **修复**：新增 `withAudio` 参数（默认开），音频约束带 echoCancellation/noiseSuppression/autoGainControl；补 `Permission.camera.request()`（被拒直接失败）与 `Permission.microphone.request()`（被拒降级为纯画面不阻断）；`cast_provider` 加 `withAudio` 状态 + `toggleAudio()`；`cast_control_panel` 加「同步手机声音」开关；`cast_service` 记录音频轨数量日志。
- **Web 端配套**：`CastReceiver.vue` 原默认 `muted=true` 且按钮无条件显示 → 新增 `hasAudioTrack` 检测（含 `onaddtrack`/`onremovetrack` 监听，音频轨可能晚到），无音频轨时不显示「开启声音」按钮，有音频时按钮高亮呼吸提示（浏览器自动播放策略必须有用户手势）。

## 服务重启速查（本地开发）

- 端口 → 服务映射：`3000` = server（node，监听 0.0.0.0）、`5173` = pc-web（vite，只监听 [::1]）、`3306` = MySQL（通常未启动）。
- **server 端改动 = 0**，所以改 flutter-app / pc-web 时 server 不用重启。
- **pc-web 走 vite HMR**，改 .vue 文件一般自动热更新；涉及 store/composable 时建议浏览器硬刷新（Ctrl+Shift+R）或重启 vite。
- **flutter-app 不是服务**，改完必须 `flutter run` 重新编译安装到手机才生效，重启 server/pc-web 都没用。
- 重启命令（PowerShell，会新开 cmd 窗口）：
  ```powershell
  Get-NetTCPConnection -LocalPort 3000 -State Listen -EA SilentlyContinue | % { Stop-Process -Id $_.OwningProcess -Force }
  Get-NetTCPConnection -LocalPort 5173 -State Listen -EA SilentlyContinue | % { Stop-Process -Id $_.OwningProcess -Force }
  Start-Process cmd -ArgumentList '/k','cd /d E:\workspace\ai-cast-hub\server && node src/index.js'
  Start-Process cmd -ArgumentList '/k','cd /d E:\workspace\ai-cast-hub\pc-web && npx vite'
  ```
- App 重新编译（Git Bash）：`cd /e/workspace/ai-cast-hub/flutter-app && /c/flutter/bin/flutter run`
  国内镜像加速（解决 flutter 命令卡在网络检查）：
  `export PUB_HOSTED_URL=https://pub.flutter-io.cn FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn`
- **改了 accessibility_service_config.xml 后，手机上必须把无障碍服务关掉再重新开启一次**，否则系统不会重新读取新配置、服务仍处于旧的无效绑定态。
